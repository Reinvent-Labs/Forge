## The Agent System

Forge runs seven specialized agents, each responsible for a distinct domain. They are independent packages that communicate through the Orchestrator — meaning you can enable, disable, or replace any agent without affecting the others.

## Common Configuration

All agents share a base configuration:

```typescript
interface AgentConfig {
  // Anthropic API key
  anthropicApiKey: string

  // Database connection
  databaseUrl: string

  // Redis for job queues
  redisUrl: string

  // How aggressively to act without approval
  autonomyLevel: 'FULL' | 'SEMI' | 'MANUAL'

  // Notification channels
  notifications: {
    slack?: { webhookUrl: string; channel: string }
    telegram?: { botToken: string; chatId: string }
  }
}
```

## Agent Lifecycle

```
1. Initialize    → Connect to DB, Redis, external APIs
2. Register      → Tell Orchestrator what events trigger this agent
3. Listen        → Wait for trigger events from the queue
4. Execute       → Run the agent's core logic
5. Report        → Write results to DB, send notifications
6. Await         → If SEMI mode, wait for human approval
7. Act           → Execute the approved action
```

## Adding a Custom Agent

Create a new package in `packages/agents/`:

```bash
mkdir packages/agents/my-agent
cd packages/agents/my-agent
npm init -y
```

Implement the `AgentModule` interface:

```typescript
import { AgentContext, AgentResult } from '@forge/orchestrator'

export class MyAgent {
  name = 'my-agent'

  async run(context: AgentContext): Promise<AgentResult> {
    // Your agent logic here
    return {
      success: true,
      summary: 'Did the thing',
      actions: []
    }
  }
}

export const myAgent = new MyAgent()
```

Register in `packages/orchestrator/src/registry.ts`:

```typescript
import { myAgent } from '@forge/agent-my-agent'
registry.register(myAgent)
```
